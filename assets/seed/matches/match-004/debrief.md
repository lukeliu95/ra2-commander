## 胜负关键（3 条）

### 1. 经济天花板：3 矿厂 6 矿车，资金从 1:20 起恒为 0（根本败因）
- 我方 `minersPerRefinery: 2 / maxMiners: 7` → 3 座矿厂只养出 **6 辆矿车**，2:53 之后再没补过。
- 25 张快照里我方资金有 **17 张为 0**，最高只到 1430（3:01）。1:13 之后再没有过"有钱可花"的时刻。
- AI 同样 3 座矿厂，却养到 **13 辆矿车**（2:01 4 → 4:01 9 → 6:01 12 → 7:41 13），**4:21 起资金常年富余 5852–7879 没花完**——它是产能受限，我们是资金受限。
- 后果直接写在部队价值曲线上：我方 3:01 峰值 4780 → 之后单调下滑 → 6:01 归零；AI 4:41 起一路 4790 → 8190 → 10600 → 12850。**7:21 时敌方 10600 : 我方 0。**
- 交换比本身不亏：全局单位价值 **杀 13320 : 损 11790 ≈ 1.13 : 1**。**我们打赢了每一场仗，但补不回损耗。**

### 2. 整局零反装甲建筑：TESLA 在资金 0 时排产，3 分 23 秒只造到 66%
- 可造列表 **2:06 就已含 TESLA**，1:48 时资金 1007、3:01 时 1430 —— 有窗口没用上（plan 的 `defenses` 只写了 `baseDef: 2`）。
- 指挥官 4:09 才补 `strongDef: 1`，4:15 借警报绕过 `credits > 700` 门槛、在资金 0 时排产，**到 7:38 仍只有 66%**，约 990 沉没。
- 于是全局只有 2 座 NALASR，6:03 / 6:18 被 V3 在射程外一座座轰掉，之后基地就是空门。
- 同期 `DRON` 权重从 1 提到 2 → 3 → 5，**一辆都没造出来**。**在资金 0 时调权重等于没调。**

### 3. 天启提前 1 分 20–35 秒，且"守得住前两波"反而把它催出来了
- **APOC 全视野首见 5:01、实时首见 4:46**；档案（match-003）是全视野 6:21 / 实时 6:23 —— 提前 **1:20（全视野）/ 1:37（实时）**，是本局与档案最大的偏差。

## 主会话补记：执行层修复（复盘后，进入 match-005 前）

针对 `runtime_issues.md` 的 B#1–B#5、A#7 和 T-018，`scripts/runtime.js` 做了以下改动（`node --check` 通过）：

- **B#1 资金饥饿**：有 ≥1000 的建筑/防御在建且资金 <300 时，暂停新排步兵和载具（矿车不受影响），记 `[reflex] 资金不足且有 ≥1000 的建筑在建`；警报只能让 ≤700 的防御跳过资金门槛，更贵的防御要攒到半价才排产（排产日志带成本和资金）。
- **B#2 队列空转**：buildOrder 完成且建筑队列空闲 >45 秒，每 60 秒记一条 warn。
- **B#3 对账不看 infantryCap**：`reconcileQueues` 增加 `infCount < infantryCap` 判断，`infantryCap` 调低会清空步兵队列。取消日志附"取消前资金"，下局可核对退款。
- **B#4 归档含弹体**：`record()` 过滤 `isMissile`。
- **B#5 `C.intel({detail:true})` 抛异常**：`avail()` 包 try/catch，失败时 `available: []` + `availableError`。
- **A#7 迷雾**：在页面上核实 `mapShroudTrait` 的 shroud 只有 0/2 两种值——**这个引擎没有战争迷雾**，探过的区域永久可见，人类玩家同样看得到，不算泄露。改为把 `visibleArmy` 拆成 `field`（离敌方出生点 >15 格，`distToMyBase/trend` 只按它算）和 `atEnemyHome`（留守单位，可当免费科技侦察）；`armyHist` 的中心点也改按 field 算。
- **T-018 拴绳外炮兵**：新增 plan 字段 `sortieMaxUnits`（默认 4，0 关闭）。拴绳外有炮兵（V3/ARTY/HOWI/DRED）在轰建筑、护卫（炮兵周围 10 格内）价值 ≤ 炮兵价值、且炮兵+护卫 ≤ 出击载具价值的 1.5 倍时，派最多 N 辆最快载具出击；护卫增强、炮兵清除或防线告警时立刻归队。
